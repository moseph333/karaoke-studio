# Karaoke Studio

Karaoke Studio turns a song from a link (YouTube, SoundCloud, Bandcamp, Vimeo, Internet Archive; Spotify, Apple Music and TIDAL songs are matched to a YouTube upload) or an uploaded file into karaoke: it separates the vocals from the backing track, fetches lyrics and times them word by word, lets you fix the timing on a live timeline, and exports 1080p60 videos, `.lrc`/`.ass` subtitles and stems. A FastAPI backend drives FFmpeg, Demucs/RoFormer separation and an MMS/DSP lyric aligner; the React + TypeScript frontend is built to `frontend/dist` and served by the backend. Local-first, optionally behind a shared passphrase, AGPL-3.0.

Read next: `README.md` (features, every env var with its default) and `docs/ARCHITECTURE.md` (API table, persistence and concurrency rules, worker protocols, frontend hooks). Both are kept current with the code; `CHANGELOG.md` (written by release-please) lists every release.

## Commands

Run from the repo root: code imports `backend.*` and `pytest.ini` sets `pythonpath = .`.

```bash
./run.sh                        # checks FFmpeg, creates venv/, installs deps (CPU torch), builds the frontend if needed, serves :8000
INSTALL_ML_EXTRAS=1 ./run.sh    # also the RoFormer extras; TORCH_INDEX_URL picks another torch build (e.g. CUDA)

# Manual setup
python3 -m venv venv && source venv/bin/activate
pip install --extra-index-url https://download.pytorch.org/whl/cpu -r backend/requirements.txt     # includes pytest, ruff, modal
pip install --extra-index-url https://download.pytorch.org/whl/cpu -r backend/requirements-ml.txt  # optional: local Balanced/Best
cp .env.example .env
cd frontend && npm install      # CI uses npm ci

# Dev servers
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
cd frontend && npm run dev      # Vite on :5173, proxies /api and /static to :8000

# Gates, as .github/workflows/ci.yml runs them (Python 3.12, Node 20)
ruff check backend && ruff format --check backend && pytest
cd frontend && npm run lint && npm run format:check && npm test && npm run build   # build = tsc && vite build
cd frontend && npm run format   # also: npm run lint:fix, npm run test:watch
cd frontend && npm run fonts    # regenerate src/fonts.css after adding a typeface or updating @fontsource

# Docker
docker compose up -d                    # image includes the ML extras; INSTALL_ML_EXTRAS=0 (compose build arg) gives a Fast-only image
docker compose --profile tunnel up -d   # adds cloudflared (needs CLOUDFLARE_TUNNEL_TOKEN)
docker compose exec karaoke-studio python -m backend.tools.fetch_models

# Tools
python -m backend.tools.fetch_models --separation all --alignment    # prefetch weights, then set *_ALLOW_DOWNLOAD=0
KARAOKE_DATA_DIR=/tmp/karaoke-demo python -m backend.tools.seed_demo  # synthetic library, no network or models
python -m backend.tools.benchmark_sync --vocals vocals.wav --truth truth.lrc --engine both
python -m backend.tools.benchmark_separation --mix song.wav --vocals ref_vocals.wav
modal deploy gpu/modal_app.py           # cloud workers, see below
```

## Architecture

- **No database.** Projects live in `projects.json` under `KARAOKE_DATA_DIR` (atomic writes, `.bak` recovery, `PROJECTS_LOCK`); media in `downloads/`, `stems/<track>/`, `output/`, `backgrounds/`, served at `/static/*`. The `projects` cache, job semaphores, cancel events (`active_cancellations`) and login rate limits are in memory, so run a single uvicorn process.
- **Backend layout.** `backend/main.py` builds the app (auth and security-header middleware, static mounts, routers, service singletons). Routes are in `backend/routers/`, domain logic in `backend/services/`, RoFormer and MMS run as child processes from `backend/workers/`. Long jobs (`pipeline.py`, `render_worker.py`, `reseparation.py`, `realignment.py`) start as FastAPI `BackgroundTasks` and share `WORKER_SEMAPHORE` (`MAX_CONCURRENT_JOBS`); their status and progress live on the project, which the UI polls.
- **Song flow** (`pipeline.run_pipeline` for links, `run_local_pipeline` for uploads):
  1. Download with yt-dlp (`services/downloader.py`, retries several YouTube player clients). `services/media_links.py` turns a pasted link into its site and a file-safe track id (a YouTube video id, else `<site>-<id>`), which names the audio, the stems folder and the project, and refuses links that are not one song (profiles, albums, playlists; an Archive item of several recordings is refused after yt-dlp reads it). Sites and domains are in `backend/assets/shared/media_sites.json`. yt-dlp needs a Vimeo login for most videos, so those fail with a sign-in error. Spotify, Apple Music and TIDAL are `lookup` sites: `services/song_lookup.py` reads the song's title, artist and length from the service's public page or API and picks a matching YouTube upload (same title, artist and length within 15 s, never another version), downloaded under the song's own track id; the song keeps the service's title and artist and records `song_match`. Those pages can change without notice; `song_lookup` is where to fix a service that stops answering.
  2. Separate (`services/separator.py`) at the song's preset from `separation_presets.py`: fast = Demucs `htdemucs` (`python -m demucs`); balanced = Mel-Band RoFormer and best = Mel-Band + BS-RoFormer averaged, both through `workers/roformer_worker.py` locally or on Modal. Falls back best → balanced → fast; `process_watchdog.py` handles cancel, timeout and stall; provenance is stored as `project.separation`. Then vocal range (`vocal_analyzer.py`) and chords (`chord_detector.py`) start on threads of their own; the song goes `ready` without waiting for them, and the studio fetches whichever is missing (`GET …/chords`, `GET …/vocal-range`), which waits for the running analysis (`project_analysis._analysis_lock`).
  3. Lyrics (`services/lyrics.py`): LRCLIB, then `syncedlyrics`, or pasted text/LRC. A fan upload's "Artist - Song" title is split when the artist is only the channel (`downloader.track_artist`); candidates are scored by name, length and file quality (`lyric_quality`); when LRCLIB writes a repeated hook once (`writes_repeats_once`), NetEase's fuller version is taken if it passes `is_fuller_transcription`. Fetched lines go through `services/lyric_cleanup.clean_fetched_lines` (notes, "x2" markers, long lines, CJK romaji into `romaji`, all caps). The lookup starts on its own thread once title, artist and length are known and runs during separation (`pipeline.LyricsPrefetch`).
  4. Align (`services/lyric_sync.sync_lyrics`): DSP pass (`aligner.py`), then the neural MMS pass (`workers/ctc_align_worker.py`, one at a time via `ALIGN_SEMAPHORE`) when available; merged per line, scored by `sync_confidence.py`, summarized in `sync_report` (with `vocal_regions` and `uncovered_vocals`). A line with `romaji` is aligned on its romaji (`lyric_sync.romaji_onto_characters`). The model's emission for a stem is saved by vocals hash (`services/emission_cache.py`, `<data dir>/alignment_cache`), so later passes on the same vocals skip the model; with `SEPARATION_REMOTE=modal` the GPU computes it right after separation.
  5. In `pipeline.sync_project_lyrics`, right after alignment: `services/repeat_fill.fill_repeats` adds the hook repeats the lyrics left out (neural engine only, lines marked `added: "repeat"`), then `services/voice_parts.assign_voice_parts` sets Singer 1 / Singer 2 by voice while every line is still Singer 1 (`project.voice_parts`). Then the first master mix (`audio_mixer.mix_and_shift`) and status `ready`.
  6. Editing: the studio saves lines (`POST /api/project/{id}/lyrics`), remixes key and guide vocal (`/mix`, cached), re-times one line (`realign-line`, saves nothing), splits and merges lines (`utils/lineSplitMerge.ts`), assigns parts by voice (`GET …/voice-parts`, applied as an edit) and names them (`part_names` via `PATCH /api/project/{id}`), and starts background jobs on finished songs: `sync_job` (`realign-lyrics` with `background: true`) and `separation_job` (`reseparate`). `background_jobs.conflict_reason` blocks overlaps with 409.
  7. Export: `/render` → `render_worker` mixes at final quality (Rubber Band), writes the `.ass` word sweep (`ass_generator.py`) and renders with FFmpeg + libass (`video_renderer.py`, bundled theme fonts in `backend/assets/fonts`), locally or on Modal. LRC, ASS, chord sheet, stems and the YouTube kit are plain GET routes.
- **Frontend** (`frontend/src`): React 18, strict TypeScript, Vite, Tailwind; no router or state library. `App.tsx` switches between the library (`TrackSearch`), `ProcessingView` and `studio/StudioWorkspace` (stage, timeline, inspector); `transport/TransportDock` owns the only `<audio>` element. Behaviour lives in `hooks/` (polling, audio, mix, editor history, quality jobs, command palette), pure helpers in `utils/`, design-system primitives in `components/ui/`, themes in `theme/` plus CSS variables in `index.css`. `api.ts` (`apiFetch`) adds the auth headers. `types.ts` mirrors `backend/schemas.py` by hand. `useProjectHistory` keeps `?project=` in the address bar and gives each opened song a history entry, so Back returns to the library. Guidance for new users: the first-song card (`studio/FirstSongCard`, `useFirstSongGuide`), the song check-up (`utils/songCheckup`, `studio/SongCheckupDialog`, opened from the song header) and Help's "Fix a problem" tab (`utils/troubleshooting`); their buttons are `GuideAction`s (`utils/guideActions`) that `useGuideActions` carries out, opening the timeline's tools through the palette's `runCommand(id)`; the failed screen's plain-language reasons are in `utils/processingErrors`; see `docs/ARCHITECTURE.md` §3.6. First load: `index.html` paints a boot shell, fonts are self-hosted (`src/fonts.css`), and the studio, export/help dialogs and command palette are deferred chunks (`deferredScreens.ts`) that `main.tsx` preloads when idle; the home screen pairs the intake card with a self-playing lyric preview (`track-search/HeroStageDemo`) and the library loads card-sized entries (`GET /api/projects?summary=1`), fetching a song in full when it is opened; see `docs/ARCHITECTURE.md` §3.6. Installable-app pieces: `public/` (`manifest.json` with a share target and app shortcuts, `sw.js`, `offline.html`, icons, screenshots), `utils/installPrompt` + `useInstallPrompt` + `InstallAppDialog`, `utils/sharedLink`, `utils/appShortcut` (`/?shortcut=new|upload|resume`), `useScreenWakeLock` (screen stays on while playing), `utils/serviceWorker`, and `backend/web_manifest.py`, which serves `/manifest.json?bg=<hex>` in the chosen app theme's colour because Android paints the bar under the gesture pill from the manifest, not the page; see `docs/ARCHITECTURE.md` §3.7.

## Cloud offload (Modal)

- `gpu/modal_app.py` defines the Modal app (default name `karaoke-studio-gpu`): `separate` runs `roformer_worker` unchanged on the first free GPU (`A10G,L40S,L4,T4`), then `ctc_align_worker --emission` on the new vocals (best effort; the emission comes back with the stems), with weights in the Modal volume `karaoke-models` (unrelated to the Docker volume of the same name); `render` runs FFmpeg on 16 CPUs with `backend/assets/fonts` mounted at `/fonts`.
- Deploy with `modal deploy gpu/modal_app.py` after `modal setup`. Deploy-time env: `SEPARATION_REMOTE_APP`, `SEPARATION_REMOTE_GPUS`, `SEPARATION_REMOTE_SCALEDOWN_SEC` (30), `SEPARATION_REMOTE_TIMEOUT_SEC` (1800, the `separate` function's own limit; the server's `SEPARATION_TIMEOUT_SEC` can only stop a job sooner), `RENDER_REMOTE_CPUS` (16). Redeploy by hand after changing the RoFormer or CTC worker, `backend/requirements-ml.txt` (installed with `audio-separator[gpu]`), the fonts or the render image's system packages (`render_image`, which installs the app image's font packages, Noto CJK included; `test_render_image_fonts.py` keeps the two lists in step); nothing redeploys it automatically.
- Server toggles: `SEPARATION_REMOTE=modal` (Balanced and Best only; Fast always runs locally) and `RENDER_REMOTE=modal`. Credentials: `MODAL_TOKEN_ID` + `MODAL_TOKEN_SECRET` in `.env` (a `~/.modal.toml` also counts). `SEPARATION_REMOTE_APP` must match the deployed name. Limits: `SEPARATION_REMOTE_QUEUE_SEC` (300), `RENDER_REMOTE_QUEUE_SEC` (120), `RENDER_REMOTE_TIMEOUT_SEC` (3600); remote separation also obeys `SEPARATION_TIMEOUT_SEC` and `SEPARATION_STALL_SEC`. Opening the Export dialog sends a beacon to `POST /api/render/warmup`, which starts a cloud CPU at most once a minute (`RENDER_REMOTE_PREWARM`, on by default) so the render doesn't wait for one. Likewise a Balanced or Best intake starts a GPU while its audio downloads (`remote_separation.warm_up`, `separate(warmup=True)`, at most every 20 s; `SEPARATION_REMOTE_PREWARM`, on by default).
- Readiness is checked offline (package and credentials present). Deploy or capacity problems surface at job time as `RemoteUnavailable`: separation skips the other cloud presets and runs Fast locally; a failed or unavailable cloud render renders locally.
- Server side: `services/modal_jobs.py` (spawn, follow an ephemeral queue, cancel), `remote_separation.py`, `remote_render.py`. Kept in sync by hand with `gpu/modal_app.py`: the `STARTED` marker, `FONTS_DIR`, function names and kwargs, and the result keys (`vocals`, `no_vocals`, `emission`, `video`). Tests fake the `modal` module, and `backend/tests/conftest.py` unsets every remote/Modal variable.

## Deployment

- Production runs in a Proxmox LXC (CT 112) on the owner's homelab: Docker-in-LXC, using this repo's `Dockerfile` and `docker-compose.yml` from a clone at `/opt/karaoke-studio`, behind Nginx Proxy Manager. The provisioning script (`scripts/deploy_karaoke_lxc.sh`), a reference compose copy (`docker/karaoke-studio/`) and the ops doc (`docs/homelab/services/karaoke.md`) live in the homelab repo (kepler).
- **Pushing to `main` deploys.** A systemd timer runs `update.sh` every 30 minutes. It should call this repo's `scripts/update_when_idle.sh`, which runs `git fetch`, moves to the new commit only once its CI run on GitHub has passed (see below), builds the image while the old container keeps serving, then drains: it writes `<data dir>/.update_draining`, and the server answers 503 to new jobs (`backend/update_drain.py`). It waits until `<data dir>/.jobs_active` reports 0 jobs (or goes stale, or `UPDATE_DRAIN_MAX_SEC`, 45 minutes by default, passes), then runs `docker compose up -d`. Before that script existed, `update.sh` ran `docker compose up -d --build` directly and cut running jobs off, without waiting for CI. After the restart it writes the commit to `<data dir>/.update_deployed`, and "nothing to update" is decided from that file, not from the checkout's HEAD (which stands in only until the file exists). If the build fails, the old container keeps running, nothing is paused, and every later run builds again until one succeeds, so a build that keeps failing needs a fix pushed.
- **The updater's CI check.** `update_when_idle.sh` asks GitHub for the newest run of the `ci.yml` workflow on the commit it is about to move to. Passed: it updates. Failed (anything but `success`): it stays on the running commit and tries again on every later call, so a fix pushed to `main` goes out by itself. Still running: it waits up to `UPDATE_CI_WAIT_SEC` (900), then leaves it for the next call. No result to read (the API cannot be reached, the origin is not on GitHub, the commit has no CI run after two minutes): it updates and logs why, as it did before the check existed, but only for a commit it has never seen failed or running. The commit last seen failed or still running is kept in `<data dir>/.update_ci_hold`; for that commit "no result" means stay, until a run passes or a newer commit arrives. `--force` does not skip the check when there is a new commit; `UPDATE_REQUIRE_CI=0` does. It resets to the commit it checked, not to wherever the branch is by then. A private repository needs `UPDATE_CI_TOKEN`. Renaming the CI workflow file means setting `UPDATE_CI_WORKFLOW` on the server, or the check finds no run. The **Update now** toast does not know about CI: with a red `main` it still offers an update that the updater then declines.
- Forced update: `POST /api/system/update` (or `POST /api/health`) with `{"action": "update"}` writes `<data dir>/.update_requested`, which a systemd path unit turns into an immediate update. Both routes need a session when `APP_PASSWORD` is set, so scripts send `X-App-Password`. With `SELF_UPDATE=1` (prod `.env`) the studio itself offers an "Update now" toast when GitHub's `main` is ahead (`hooks/useServerUpdatePrompt.ts`); it stays off elsewhere, where nothing applies the request.
- Prod config exists only in CT 112's `.env`, which updates leave alone: `SEPARATION_REMOTE=modal`, `SEPARATION_QUALITY=best`, `RENDER_REMOTE=modal` and a dedicated Modal token. New env vars need safe defaults. An untracked `docker-compose.override.yml` there sets `ulimits: core: 0`.
- The prod CPU has AVX but no AVX2/AVX-512: local RoFormer is very slow there and PyTorch can die with SIGILL, so Balanced and Best depend on Modal and Fast is the local fallback. 4 vCPUs, 6 GB RAM, a 40 GB disk shared with Docker's build cache.

## Conventions

- Python: ruff for lint and format (target py312, line length 100, double quotes; rules in `pyproject.toml`). Modules open with a docstring. Reach shared singletons (`separator`, `audio_mixer`, `lyrics_service`, `WORKER_SEMAPHORE`, `projects`, ...) through `import backend.main as main_mod` at call time; tests monkeypatch them there. Background jobs look the project up again before every write and save under `PROJECTS_LOCK`. Request handlers that report an edit as saved call `save_projects(strict=True)` inside `restore_on_failed_save(proj, keys)`, so a full disk answers 507 and rolls the edit back; background and progress saves stay soft. Routes that start new work (`/process`, uploads, `/render`, `/reseparate`) call `ensure_free_space()` after their 404, 409 and request checks (an upload's file-content check comes after).
- Frontend: Prettier (single quotes, semicolons, width 100), ESLint with `--max-warnings 0` (warnings fail CI), strict TS. Colour only through theme tokens (`bg-theme-*`, `text-theme-*`): `designTokenGuard.test.ts` fails on Tailwind palette classes like `bg-slate-800` in `components/` or `App.tsx`. Modals use `components/ui/Dialog`; tests enforce 44 px touch targets and unique accessible names at phone and desktop widths.
- Tests: one folder per feature, `backend/tests/<feature>/test_*.py` (alignment, chords, subtitles, render, projects, server, ... and `e2e/`) and `frontend/src/tests/<feature>/*.test.ts(x)` (stage, timeline, transport, theme, accessibility, pwa, ...; Vitest, jsdom, Testing Library). `backend/tests/conftest.py` and `frontend/src/tests/setup.ts` stay at the top and cover every folder. Shared generators and fixtures go in each suite's `helpers/`, never in another test file. pytest imports test files by basename (there is no `__init__.py`), so a new file's name must be unique across folders; the `meta/` layout tests check that and that no test file sits at the top level. File names say what the file tests (`test_chords_api_backfill.py`, `transportDockScrubbing.test.tsx`); 2.0-era files also use sentence-style test names, while older files' docstrings and test names still carry labels from earlier agent runs (`Challenger`, `Milestone`, `iter2`). ML engines run as fake worker processes and stub packages, so neither suite needs model weights or network; tests that reach the NetEase step stub `syncedlyrics.search`. Real lyric listings of two songs (LRCLIB and NetEase) are in `backend/tests/helpers/lrclib_listings.py`, synthetic one- and two-voice stems in `helpers/voices.py`.
- Commits: Conventional Commits, `type(scope): summary`, the summary in plain lowercase English describing the effect (`fix(stems): keep lyric edits saved while a re-separation re-times words`). Types: feat, fix, docs, test, style, chore. Bodies are wrapped prose on what was wrong and what changed.
- Releases are cut by release-please (`.github/workflows/release-please.yml`, `release-please-config.json`, `.release-please-manifest.json`). It keeps a release PR (`chore(main): release X.Y.Z`) open on `main` that collects the commits since the last release, bumps `DEFAULT_APP_VERSION` in `backend/config.py` (the line marked `x-release-please-version`), `version` in `frontend/package.json` and its lock, and writes `CHANGELOG.md`. Merging that PR tags the commit `vX.Y.Z` and publishes a GitHub Release. Do not bump those versions, edit `CHANGELOG.md` or tag by hand. The version comes from the commit subjects on `main` (the PR title, with squash merges): `fix` is a patch, `feat` a minor, `feat!`/`fix!` or a `BREAKING CHANGE:` footer a major; `docs`, `test`, `style` and `chore` alone release nothing and stay out of the changelog. To force a version, put `Release-As: X.Y.Z` in a commit body. The running version is `APP_VERSION`, else `git describe --tags --always` (compose mounts `.git` read-only), else that default. The README's "What's new" sections are hand-written highlights and optional.

## Gotchas

- `backend/config.py` reads the repo-root `.env` at import (real env vars win) and creates the `KARAOKE_DATA_DIR` folders (default `./workspace_data`) on import. It also reads `ALLOWED_ORIGINS` (comma-separated CORS list) and `APP_VERSION`, which `.env.example` does not list.
- Auth: an empty `APP_PASSWORD` means open access. When set, `/api/*` (except `GET /api/health` and `/api/auth/*`) and `/static/*` need a session token or the raw passphrase (`X-App-Password`, `Authorization: Bearer`, or a cookie); without one, `GET /api/health` ignores `check_remote`. Wrong passphrases at login and in headers or cookies on any route share one rate limit (each distinct value once per window; expired tokens signed with the passphrase don't count), and a limited IP gets 429 even with valid credentials. It keys on the `X-Forwarded-For` entry `FORWARDED_TRUSTED_HOPS` places from the end (default 1, the nearest proxy's; cloudflared in front of Nginx Proxy Manager needs 2), so port 8000 must only be reachable through the proxy. Tokens are HMAC-signed with a key derived from the passphrase and the server secret (`SESSION_SECRET`, else `<data dir>/.session_secret`, created on first use) and last 7 days, so changing either signs everyone out; tests that hand-sign a token use `auth.session_signing_key`. `conftest.py` sets a test passphrase when none is set: use the `client` fixture, or `unauth_client` for 401 cases.
- Models download on first use into `TORCH_HOME`, `AUDIO_SEPARATOR_MODEL_DIR` and `ALIGNMENT_MODEL_DIR` (Docker: the `karaoke-models` volume at `/models`): Demucs about 80 MB, each RoFormer 0.6–0.9 GB, MMS about 1.2 GB. The MMS aligner is CC-BY-NC 4.0 (non-commercial); `ALIGNMENT_ENGINE=dsp` never uses it. The `librosa<1.0` pin in `requirements-ml.txt` is deliberate (audio-separator 0.47 needs audioread).
- Never commit `.env`, `client_secret.json`, `token.json`, `workspace_data/` or `frontend/dist/`. `.gitignore` also ignores every `*.png`, `*.jpg`, `*.webp`, `*.wav`, `*.mp4` and `*.ass` outside `docs/` and `frontend/public/`; tests generate their media at run time.
- Shared with the frontend: `backend/assets/shared/*.json` (stage presets' names and colours, singer labels, song-link sites and their host cases, upload limits, confidence thresholds, background motion, tokenizer cases, word-spread cases, ad-lib cases, uncovered-vocals thresholds), read by `backend/shared_assets.py` and imported by the frontend as `@shared/<name>.json`; the Docker frontend stage copies that folder. Still hand-synced: each stage preset's export-only style (`_EXPORT_STYLES` in `ass_generator.py`) and stage-only fields (`STAGE_VIEWS` in `stagePresets.ts`); app themes across `theme/appThemes.ts`, `index.css`, the boot script in `index.html` and `public/manifest.json` (compared by `themeRegistryParity.test.ts`); the lyric tokenizer in `backend/services/lyric_tokenize.py` and `frontend/src/utils/lyrics.ts`, with how tokens are written back out (`space_after`/`join_lyric_tokens` and `spaceAfterTokens`/`joinLyricTokens`: the source text's spacing, never spaces around CJK characters) (both suites run `backend/assets/shared/tokenize_cases.json`, whose `written` and `joined` fields pin the spacing); the ad-lib rule, words inside parentheses (`adlib_flags` in `lyric_tokenize.py`, `adlibFlags` in `utils/lyrics.ts`; both run `adlib_cases.json`); the vocals-without-lyrics rule (`sync_confidence.uncovered_vocals`, `utils/uncoveredVocals.ts`; thresholds in `uncovered_vocals.json`); the editor's even word spread in `backend/services/lyric_sync.py` (`words_spread_evenly` and its helpers `_spread_weight`, `_SPREAD_PUNCTUATION` and `SPREAD_TOLERANCE`), mirrored by `frontend/src/utils/lyrics.ts` (`wordSpreadWeight`) and `utils/manualEdits.ts` (`wordsSpreadEvenly`, `SPREAD_TOLERANCE`) (both suites run `backend/assets/shared/word_spread_cases.json`). Theme ids differ from display names (`punk_diy` = Basement Flyer, `tape_studio_70s` = Reel-to-Reel '74, `dive_bar_crt` = Midnight KTV Booth, `clean_paper` = Monolith Press).
- Service worker (`frontend/public/sw.js`): it must never handle `/api` or `/static` or serve the page from cache, or audio, projects and the reload prompt (`useUpdatePrompt`) go stale. Bump its cache names when changing what it precaches. `sw.js`, `offline.html` and `manifest.json` are served `no-cache` (`backend/http_delivery.py`). It only registers in production builds.
- Never put `overscroll-behavior: none` or `contain` on `body`: `html` and `body` both set `overflow-x: hidden`, so `body` is a scroll container that never scrolls, and blocking its overscroll kills touch scrolling on phones. Put it on `html` (`standaloneScrollGuard.test.ts` checks).
- Fonts: the page loads nothing from other sites. A theme or stage preset that names a new web font needs its `@fontsource` package, an entry in `frontend/scripts/generate-fonts-css.mjs` and `npm run fonts`; `selfHostedFonts.test.ts` fails when `src/fonts.css` and the font stacks disagree. Never import a `@fontsource-variable` package's CSS directly: it names the family "Sora Variable", which no stack uses.
- First-run UI (the first-song card) renders in every App-level test, because `tests/setup.ts` clears storage after each test: give its controls names no other studio control has (`studioAccessibleNameUniqueness.test.tsx`), keep it out of non-wrapping flex rows (the overflow checks estimate a button's width from all its text, `sr-only` included), and never give in-page guidance `role="dialog"`, which turns the keyboard shortcuts off (`isModalActive`). `LyricTimelineEditor.tsx` has a 430-line limit enforced by tests: new timeline UI goes in a child component.
- Guidance copy is in two places kept in step by hand: `frontend/src/utils/troubleshooting.ts` (Help's "Fix a problem") and the README's "When results are off" table.
- Deferred screens: components imported through `deferredScreens.ts` render asynchronously the first time in a test. A test that opens the studio, a dialog or the palette and asserts synchronously needs `beforeAll(() => loadDeferredScreens())`. Do not import them in `tests/setup.ts` (modules loaded there escape `vi.mock`).
- The manifest's icons and screenshots are committed PNGs in `frontend/public`, as is `og-image.png` (the link preview, a 1200×630 capture of the first-visit home screen). Regenerate them (from `icon.svg` / `icon-maskable.svg`, and a `seed_demo` library for screenshots) when the icon or the look changes; `tests/pwa/pwaManifestInstall.test.ts` checks their sizes against the manifest. The app shortcuts' icons (`frontend/public/shortcuts/*.png`) are rendered from the SVGs beside them at 96 and 192 px; `tests/pwa/appShortcuts.test.tsx` checks them.
- Changing what the mixer produces: bump `MIX_CACHE_VERSION` in `backend/master_audio.py` so cached mixes and older renders are rebuilt.
- `pytest.ini` always adds `--cov=backend` and `pyproject.toml` sets `fail_under = 50`, so running a subset can fail on coverage alone (pytest-cov's `--no-cov` turns it off). A few tests assert wall-clock budgets and can flake on slow CPUs. CI installs FFmpeg with libass (`ffmpeg libass-dev`) for the backend suite; a couple of tests skip without FFmpeg or its rubberband filter.
- `run.sh` rebuilds `frontend/dist` only when it is missing or the `frontend/src` directory itself is newer, so edits to existing files can leave a stale build. The backend mounts `frontend/dist` at `/` only if it exists at startup.
